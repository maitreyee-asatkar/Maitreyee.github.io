# Security Incident Response — Sample Policy

This document is fictional portfolio data and does not represent an organization's actual policy.

## Suspected phishing

Employees who suspect a phishing message should avoid clicking links or opening attachments, report the message through the organization's approved reporting mechanism, and contact the IT/security team if they interacted with the message.

## Lost or stolen device

A lost or stolen company device should be reported to the IT/security team as soon as possible. The security team should assess whether remote lock, remote wipe, credential reset, or additional investigation is appropriate.

## Security events

Security analysts should preserve relevant evidence, document the observed indicators, record affected accounts or assets when known, and escalate incidents according to the organization's incident response process.

## Access control

Access should be granted according to least-privilege principles. Privileged access should be limited to authorized personnel and reviewed periodically.

## Evidence limitation

This sample policy is intentionally small. The assistant must not infer requirements that are not explicitly present in the indexed documents.
